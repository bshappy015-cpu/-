# 포스트룸 에이전트 팀 파일

총괄 1개와 실무 4개로 운영하는 팀의 역할 지침이다. 파일은 한국어 Markdown이며 특정 서비스의 자동 등록 설정 파일이 아니다.

## 사용법

프로젝트 루트에 `AGENTS.md`와 `agents/`를 함께 둔다. 기존 `AGENTS.md`가 있으면 내용을 비교해 팀 규칙을 병합하고 기존 지침은 보존한다. 루트 지침을 읽는 개발 도구에서 사용하거나, 총괄에게 루트 지침을 읽도록 명시한다. 도구에 하위 에이전트 기능이 있어야 실제 역할을 나눠 실행할 수 있다.

총괄은 작업에 필요한 역할 문서를 해당 에이전트에게 읽히고 범위와 완료 기준을 전달한다. 역할 문서는 도구의 에이전트 수·권한·모델 설정을 변경하지 않는다.

### 사용자 요청 예시

```text
AGENTS.md의 팀 운영 규칙을 따라 포스트룸 작업 보관함을 개선해 줘.
여러 매물을 저장하고 다시 열 수 있어야 하고, 새로고침해도 사진이 남아야 해.
기존 작업을 보존하면서 기획·디자인·구현·독립 검증을 진행해 줘.
```

이것은 요청 예시이며, 해당 기능의 제작이 이 팀 파일만으로 승인되거나 실행되는 것은 아니다.

### 총괄이 전달하는 업무 예시

```text
역할 / 읽을 역할 문서: product-planner / agents/product-planner.md
목표와 사용자 가치: 여러 매물 원고를 잃어버리지 않고 다시 편집하기
현재 확인된 사실 / 가설: 먼저 현재 저장·복원 구현을 확인할 것
관련 파일·자료: 현재 저장소, 앱 README, 저장·복원 코드
담당 범위와 파일 / 변경 가능 여부: 분석·기획 문서만 작성, 제품 코드는 수정하지 않음
선행 산출물과 제약: 기존 저장 데이터 보존, 현재 기술 스택 우선
완료 기준과 검증 방법: 이용 흐름, 예외 상황, 우선순위, 검증 가능한 완료 기준 제시
이번 범위에서 제외할 것: 결제, 회원가입, 외부 서비스 연동
```

## 권장 작업 크기

- 문구·작은 버그: 총괄이 필요한 담당자만 배정한다.
- 사용자 흐름이 달라지는 기능: 기획 → 디자인 → 개발 → 품질 검증.
- 독립적인 조사와 기존 코드 분석: 병렬 진행 가능하되 변경 파일은 겹치지 않게 한다.

팀 파일만 추가된 상태와 앱이 구현·검증된 상태는 구분해서 보고한다.
